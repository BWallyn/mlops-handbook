# Applying MLflow to Your Kedro Project

> **Goal:** Integrate MLflow experiment tracking into your Kedro pipeline, logging from inside node functions, against a local MLflow tracking server.
> This document is a step-by-step guide paired with a completion checklist. Work through the steps in order — each section builds on the previous one.

---

## Step 1 — Install MLflow

Add MLflow to your project dependencies.

In `pyproject.toml`:

```toml
[project]
dependencies = [
    "mlflow>=2.13",
    # ... your other dependencies
]
```

Then install:

```bash
pip install -e ".[dev]"
# or, if you manage dependencies directly:
pip install mlflow
```

Verify the installation:

```bash
mlflow --version
```

---

## Step 2 — Start the Local Tracking Server

MLflow's local server persists run data to a `mlruns/` directory in whatever folder you launch it from. Always launch it from your **Kedro project root** so all runs are stored in one place.

```bash
# From your Kedro project root
mlflow ui --host 127.0.0.1 --port 5000
```

Open `http://127.0.0.1:5000` to confirm the UI is running. Leave this terminal open while you work — the server must be running for your nodes to log successfully.

> **Tip:** Add `mlruns/` to your `.gitignore` if it isn't already. Run data belongs on the tracking server, not in version control.

```bash
# .gitignore
mlruns/
mlartifacts/
```

---

## Step 3 — Set the Tracking URI

Your Kedro nodes need to know where to send tracking data. Set the tracking URI via an environment variable — never hardcode it in a node.

```bash
export MLFLOW_TRACKING_URI=http://127.0.0.1:5000
```

Add this to your shell profile (`.bashrc`, `.zshrc`) or a local `.env` file that you source before running pipelines:

```bash
# .env (do NOT commit this file)
MLFLOW_TRACKING_URI=http://127.0.0.1:5000
```

To verify the variable is set:

```bash
echo $MLFLOW_TRACKING_URI
# Expected: http://127.0.0.1:5000
```

Add `.env` to `.gitignore`:

```bash
# .gitignore
.env
mlruns/
mlartifacts/
```

## Step 4 — Create a Git Hash Utility

Add this helper to your project package so every node can log the git commit hash without duplicating code.

```python
# src/<your_package>/__init__.py  or  src/<your_package>/utils.py

import logging
import subprocess

logger = logging.getLogger(__name__)


def get_git_commit_hash() -> str:
    """Return the current short git commit hash.

    Returns:
        The 8-character git commit hash, or 'unknown' if unavailable.
    """
    try:
        result = subprocess.run(
            ["git", "rev-parse", "--short", "HEAD"],
            capture_output=True,
            text=True,
            check=True,
        )
        return result.stdout.strip()
    except subprocess.CalledProcessError:
        logger.warning("Could not retrieve git commit hash.")
        return "unknown"
```

## Step 5 — Add MLflow Parameters to Your Config

All hyperparameters logged to MLflow must come from `conf/base/parameters/`. Never hardcode them in a node function.

Identify the parameters your training node already uses and confirm they live in the appropriate parameters file, for example:

```yaml
# conf/base/parameters/<your_pipeline>.yml

# Model hyperparameters
n_estimators: 200
max_depth: 8
learning_rate: 0.05
random_state: 42

# Evaluation
test_size: 0.2

# MLflow
experiment_name: "<your_modelling_task>"  # e.g. "churn_prediction"
```

The `experiment_name` field is the one value that controls which experiment bucket your runs land in inside the MLflow UI. Name it after the modelling task, not the method.

## Step 6 — Instrument Your Training Node

Open the node function responsible for model training in your pipeline. Apply the following pattern:

```python
# src/<your_package>/pipelines/<your_pipeline>/nodes.py

import logging
from typing import Any

import mlflow
import mlflow.sklearn  # swap for mlflow.xgboost, mlflow.pytorch, etc.
import pandas as pd
from sklearn.base import BaseEstimator  # or your model's base class

from <your_package>.utils import get_git_commit_hash  # adjust import path

logger = logging.getLogger(__name__)


def train_model(
    features: pd.DataFrame,
    target: pd.Series,
    params: dict[str, Any],
) -> BaseEstimator:
    """Train your model and log the run to MLflow.

    Args:
        features: Feature matrix.
        target: Target vector.
        params: Hyperparameters from conf/base/parameters/<your_pipeline>.yml.

    Returns:
        The fitted model.
    """
    from sklearn.model_selection import train_test_split
    # Replace with your actual model import
    from sklearn.ensemble import RandomForestClassifier

    X_train, X_val, y_train, y_val = train_test_split(
        features,
        target,
        test_size=params["test_size"],
        random_state=params["random_state"],
    )

    mlflow.set_experiment(params["experiment_name"])

    with mlflow.start_run():
        # 1. Tag with git hash first — always
        mlflow.set_tag("git_commit", get_git_commit_hash())

        # 2. Log all hyperparameters before training
        mlflow.log_params(
            {
                "n_estimators": params["n_estimators"],
                "max_depth": params["max_depth"],
                "random_state": params["random_state"],
                "test_size": params["test_size"],
            }
        )

        # 3. Train
        model = RandomForestClassifier(
            n_estimators=params["n_estimators"],
            max_depth=params["max_depth"],
            random_state=params["random_state"],
        )
        model.fit(X_train, y_train)

        # 4. Evaluate and log metrics
        # Replace with your actual metrics
        from sklearn.metrics import f1_score, roc_auc_score
        y_pred = model.predict(X_val)
        y_prob = model.predict_proba(X_val)[:, 1]

        mlflow.log_metrics(
            {
                "val_f1": f1_score(y_val, y_pred),
                "val_roc_auc": roc_auc_score(y_val, y_prob),
            }
        )

        # 5. Log the model artifact
        mlflow.sklearn.log_model(model, artifact_path="model")

        logger.info("MLflow run logged successfully.")

    return model
```

**Adapt to your project:**
- Replace `RandomForestClassifier` with your actual model class.
- Replace `mlflow.sklearn` with the appropriate MLflow flavour (`mlflow.xgboost`, `mlflow.pytorch`, etc.).
- Add or remove `log_params` keys to match your actual hyperparameter set.
- Replace the metrics block with the metrics relevant to your task (regression: `rmse`, `mae`; classification: `f1`, `roc_auc`, `precision`, `recall`).

## Step 7 — Run the Pipeline and Verify

Run your Kedro pipeline as normal:

```bash
kedro run --pipeline <your_pipeline>
```

Then open the MLflow UI at `http://127.0.0.1:5000` and confirm:

- Your experiment appears by name in the left sidebar.
- The run shows the correct parameters.
- The metrics are populated.
- The `git_commit` tag is set.
- The model artifact is listed under the run's **Artifacts** tab.

If the run does not appear, check that `MLFLOW_TRACKING_URI` is set in the shell where you ran `kedro run`, and that the MLflow server is still running.

---

## Step 8 — Run Multiple Experiments and Compare

Change one hyperparameter in `conf/base/parameters/<your_pipeline>.yml` and run the pipeline again. Repeat for a third configuration.

In the MLflow UI:
1. Select all three runs using the checkboxes.
2. Click **Compare** to open the parallel coordinates plot and metric comparison table.
3. Identify which parameter combination produced the best validation metric.

This is the core loop of experiment tracking — the UI is not just a log, it is a comparison tool.

## Completion Checklist

Work through this list after completing all steps. Each item maps to a step above.

### Setup

- [ ] `mlflow` added to `pyproject.toml` dependencies and installed
- [ ] `mlflow ui` launches without errors from the project root
- [ ] `http://127.0.0.1:5000` is accessible in the browser
- [ ] `mlruns/` and `mlartifacts/` are in `.gitignore`
- [ ] `MLFLOW_TRACKING_URI=http://127.0.0.1:5000` is set in the environment

### Code

- [ ] `get_git_commit_hash()` utility exists and is importable from the package
- [ ] Training node uses `with mlflow.start_run():` (not `start_run()` / `end_run()`)
- [ ] `mlflow.set_tag("git_commit", ...)` is the first call inside the run
- [ ] All hyperparameters are logged via `mlflow.log_params()` **before** `model.fit()`
- [ ] All hyperparameter values come from `params` dict (i.e. from `conf/base/parameters/`) — no hardcoded values passed to `log_params`
- [ ] Validation metrics are logged via `mlflow.log_metrics()`
- [ ] Model is logged via `mlflow.sklearn.log_model()` (or equivalent flavour)
- [ ] `experiment_name` is set in `conf/base/parameters/<your_pipeline>.yml` and passed to `mlflow.set_experiment()`

### Verification

- [ ] `kedro run` completes without MLflow-related errors
- [ ] Run appears in the MLflow UI under the correct experiment name
- [ ] Parameters tab shows all expected hyperparameters with correct values
- [ ] Metrics tab shows all expected metrics with correct values
- [ ] Tags tab shows `git_commit` with a valid hash (not `"unknown"`)
- [ ] Artifacts tab shows the logged model
- [ ] At least 3 runs exist with different hyperparameter configurations
- [ ] Runs have been compared in the MLflow UI using the Compare view

## Common Errors

**Run appears in `mlruns/` locally but not in the UI at port 5000.**
The `MLFLOW_TRACKING_URI` environment variable was not set when `kedro run` was executed. Kedro nodes defaulted to logging locally instead of to the server. Set the variable and re-run.

**`git_commit` tag shows `"unknown"`.**
The pipeline is running outside a git repository, or `git` is not on the PATH in the environment. Verify with `git rev-parse --short HEAD` in the same shell.

**`mlflow.set_experiment()` raises `MlflowException: Could not find experiment`.**
The tracking server is not running or the URI is wrong. Confirm the server is up at `http://127.0.0.1:5000` and that `MLFLOW_TRACKING_URI` matches.

**Model artifact is missing from the Artifacts tab.**
`mlflow.sklearn.log_model()` was called outside the `with mlflow.start_run():` block, or not called at all. Verify indentation.
